# architecture
- Values single-source-of-truth / canonical identity patterns — strongly prefers "identity linking" (storing `identityId` references to a central ID provider) over recreating duplicate user records across services. Anti-fragmentation is a core design principle for the ArcevoCirqle ecosystem. Confidence: 0.85
- Prefers a dedicated canonical identity/auth service (arc-id) over per-app auth implementations — downstream apps (e.g. arcbase) should consume identity from that provider (auth, OAuth, MFA, passkeys) rather than owning their own user tables for identity data. Confidence: 0.85
- Welcomes the agent validating/confirming architectural mental models back to them (e.g. "Does this align with what you had in mind?") — they're explicit they "might be wrong" and value the agent surfacing understanding rather than silently proceeding. Confidence: 0.7
- Wants sibling projects referenced for pattern consistency (e.g. "if you look into arcid at ../arc-id... you will discover a pattern") — expects the agent to cross-reference established sibling services to find and follow existing conventions rather than inventing new ones. Confidence: 0.8
- Concerned about schema/architecture drift — proactively asks the agent to confirm models fully align with the system's goal and to flag any missing models or definitions before proceeding ("if there are any missing models or definition in the schema - we might have a drift"). Confidence: 0.8
- Values the consistent module pattern from arc-id (presenter, controller, repository, route, flow, plugin — ~five files per module) and is open to mirroring it across sibling services like arcbase for structural consistency across the ecosystem. Confidence: 0.75
- Prefers building on the @arcevo/facet-* packages (components, layout, store, sdk) as the complete foundational building blocks — from components to layout — rather than reinventing UI/layout/store concerns, since they're considered more than sufficient for a great build. Confidence: 0.8
